# RoadForge 3D

Локальный 3D/2D-редактор дорожной сети OpenStreetMap. Vue 3 + TypeScript + Vite + Pinia + Babylon.js. Карта и правки остаются в браузере; сервер, регистрация и API-ключи не нужны.

Два раздела: **Редактирование** и **Транспорт**. Кнопка **«Проверка»** в верхней панели открывает список ошибок сети в любом разделе.

## Исправленная карта

Готовая карта для сдачи — [`maps/example-edited.osm`](maps/README.md). Там же таблица правок с OSM ID: что было, что стало и почему.

Исходный файл организаторов почти исправен. Красная подсветка дорог в основном шла от ложных срабатываний проверки редактора: подъезды, касающиеся стены у арки, петли и куски сети на границе выгрузки. Проверка исправлена. Настоящая ошибка одна: проезды под семью зданиями были размечены как подземные (`layer=-1`). Импортёр Webots такие дороги не загружает, и сеть рвалась у этих домов. Теперь это арки на уровне земли (`tunnel=building_passage`).

## Запуск

Нужен Node.js 22+; проверено на Node.js 22 и 24.

```bash
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Пример Иркутска загрузится автоматически. «Открыть карту» загружает другой `.osm`. `npm install` тоже работает, но для воспроизводимой установки лучше `npm ci`.

```bash
npm run test
npm run build
npm run preview
```

Браузерный сценарий:

```bash
npx playwright install chromium
npm run test:e2e
```

Тест использует системный Chromium из `/usr/bin/chromium`, если он есть, иначе браузер Playwright. Другой исполняемый файл задаётся через `CHROMIUM_PATH`. Если в Linux не хватает системных библиотек, используйте `npx playwright install --with-deps chromium`.

## Редактирование

- **Дорога.** Нажмите на дорогу. Справа настраиваются только **число полос** и **направление каждой полосы**. Нажатие на полосу меняет её направление: ↑ — по стрелкам на выбранной дороге, ↓ — навстречу. В OSM записываются `lanes`, `oneway`, `lanes:forward` и `lanes:backward`. OSM хранит только число полос в каждом направлении, поэтому полосы одного направления стоят рядом (попутные справа). Стрелки направления видны прямо на полосах выбранной дороги.
- **J — соединить полосу с другой дорогой.** Выберите полосу кликом по ней, нажмите J и кликните по полосе другой дороги у общего перекрёстка. Связь сохраняется OSM-отношением `type=connectivity`. Фиолетовая линия показывает связь, машины и автобусы едут по ней. Список связей с кнопкой «Убрать» — в свойствах дороги. Если дороги ещё не соединены, J присоединяет ближайший конец выбранной дороги к другой дороге общим узлом.
- **D — новая дорога.** Клики рядом с существующими узлами и сегментами привязываются к ним. Пересечение с наземной дорогой получает общий узел автоматически. Enter завершает дорогу, Escape отменяет.
- **M / I — узлы дороги.** Перетащите вершину выбранной дороги или вставьте новую на сегменте. Общий узел меняется во всех дорогах. Узлы зданий не редактируются.
- **Здания** не создаются и не редактируются: редактор занимается дорогами. Выбранное здание можно только удалить.
- Удаление дороги и здания требует подтверждения. Все правки поддерживают Undo/Redo и сохраняются при экспорте `.osm`.
- **Поиск** находит улицу по названию.

## Транспорт

- Движение правостороннее. Машины и автобусы — локальный предпросмотр: они не экспортируются в OSM и не заменяют SUMO/MATSim.
- Машина, доехавшая до конца дороги (тупик или нет разрешённого выезда), исчезает. Встречные машины на узкой дороге разъезжаются, а простоявшая дольше 8 секунд убирается с карты, поэтому ожидающие машины не копятся.
- **B — остановка.** Нажмите рядом с дорогой с нужной стороны (контур показывает место): остановка встанет слева или справа от проезжей части, а не посередине. По стандарту OSM PTv2 записываются точка остановки на дороге (`public_transport=stop_position`), платформа сбоку (`public_transport=platform`, `highway=bus_stop`) и их группа `public_transport=stop_area`.
- **R — маршрут автобуса.** Выберите остановки по порядку, введите название и сохраните. Маршрут записывается OSM-отношением `type=route` + `route=bus`. Автобус останавливается на каждой остановке на 3 секунды и продолжает движение по кругу, если есть обратный путь.

## Проверка

Кнопка **«Проверка · N»** показывает число реальных проблем и открывает панель ошибок. «Показать» приближает место. Кнопки исправления:

| Проблема | Исправление |
|---|---|
| Дорога проходит сквозь здание | «Проезд через арку»: участок внутри здания становится `tunnel=building_passage`, подъезды остаются на уровне земли. Габариты арки не задаются. |
| Проезд под зданием размечен как подземный (`layer<0`) | «Сделать проезд на уровне земли»: арка `tunnel=building_passage` или, под навесом, `covered=yes`. |
| Пересечение дорог без общего узла | «Соединить узлом» |
| Конец дороги почти касается другой | «Замкнуть разрыв» |

Касание стены в общем узле, петли, короткие отростки и куски сети, уходящие за границу выгрузки, ошибками не считаются. Все проверки эвристические, поэтому каждую правку сверяйте с реальной картой («Сверить с картой»).

## Сохранение

«Сохранить карту» (Ctrl/Cmd+S) сначала проверяет файл: ошибки XML и ссылок, конфликты геометрии, отдельные части сети, направления. При проблемах можно исправить их или скачать `-draft.osm`. Экспорт сохраняет XML-декларацию исходного файла. Для сдачи переименуйте файл в название команды.

### Windows и ошибка Babylon.js gpuPicker.js.map

Обновите ветку и выполните `npm ci`, затем `npm run dev`. Перед запуском автоматически проверяется исходная карта `node_modules/@babylonjs/core/Collisions/gpuPicker.js.map`. При некоторых неполных npm-установках она повреждена и вызывает `Unterminated string literal`. Повреждённая карта отладки удаляется, код Babylon.js не меняется. Если ошибка осталась, очистите кеш `node_modules/.vite` и перезапустите с `npm run dev -- --force`.

### Docker

```bash
docker build -t roadforge-3d .
docker run --rm -p 8080:80 roadforge-3d
```

Откройте http://localhost:8080. На этапе сборки образ запускает модульные тесты и production build.
