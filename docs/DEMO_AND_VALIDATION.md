# Защита RoadForge: показать доказуемый результат

## Что изменено

- Физическая полоса определяет направление автомобиля кликом. Общий код учитывает сторону движения, `oneway=yes/1/true/-1/no`, круговое движение, `lanes:forward`, `lanes:backward`, `lanes:both_ways`.
- Предпросмотр по запросу команды запускается в левостороннем режиме. Переключатель меняет только предпросмотр и интерпретацию выбранных полос; не переписывает теги и не меняет направление OSM way. Для карты Иркутска сверять режим с реальными правилами и настройками адаптеров организатора. Для серверного пайплайна одно переключение в браузере ничего не доказывает.
- Полосы в `turn:lanes`, `change:lanes`, `maxspeed:lanes` записываются слева направо по ходу соответствующего потока. Для обратной односторонней дороги применяются общие `*:lanes`.
- Не создаётся транспорт поверх другого транспорта на той же полосе. При переходе на занятый сегмент машина ждёт, автобус сохраняет индекс маршрута. В тупике транспорт останавливается вместо мгновенного разворота.
- Мелкие шаги расчёта и ограничение перемещения по дистанции до лидера защищают очередь при ускорении времени. Скорость в mph переводится в км/ч; нулевое ограничение не превращается в 5 км/ч.
- Панель показывает число движущихся и ожидающих машин и текущую среднюю скорость. Эти числа относятся к локальному предпросмотру.
- «Проверка → Отчёт до / после для защиты» сохраняет JSON: числа объектов, предупреждения по кодам, входы/выходы направленной сети, ID добавленных/удалённых/изменённых объектов и применённые действия. После Undo сравнение отражает текущее состояние. Направленные тупики могут быть нормальной границей выгрузки, их нужно проверять вручную.

## Сценарий демонстрации на 5 минут

1. Открыть исходный `example.osm`, показать один подтверждённый по карте разрыв или перекрёсток без общего узла. Записать ID и координаты.
2. Показать 2D и 3D одного места. Соединить дороги вручную, объяснить, почему здесь нет моста/тоннеля. Undo/Redo показывает обратимость.
3. Исправить число и направления полос или светофор, если это подтверждено источником. Добавить машину на каждую сторону и показать допустимые направления.
4. При необходимости показать две остановки, построение автобусного маршрута и остановку автобуса. Не выдавать локальный трафик за SUMO.
5. Скачать OSM, снова открыть его и проверить сохранённые правки. Скачать отчёт до/после до повторного открытия: новый импорт начинает новую базу сравнения.
6. Отправить файл на сервер организатора под именем команды. Показать настоящие три видео и одну и ту же правку на каждом уровне. Если прогона ещё нет, обозначить это прямо.

## Идеи с наибольшей ценностью для следующего этапа

1. **Сравнение серверных прогонов:** два видео SUMO/Webots рядом, одинаковое место и время, отметки правок из JSON. Доказательство эффекта редактирования, а не только интерфейса.
2. **Проверка маршрута A → B:** поиск с учётом turn restrictions и подсветкой конкретной причины недоступности. Потребует общего графа для автобусов и машин и корректной поддержки via-way relations.
3. **Геопривязанная подложка:** лицензированный источник снимков/схемы, прозрачность и дата источника. Текущая карта рядом с редактором не заменяет такую подложку.
4. **Профили дорожных элементов:** проверенные шаблоны остановки, регулируемого перекрёстка и моста с показом всех OSM-тегов перед применением.
5. **Профиль высоты дороги:** контроль уклона и плавного сопряжения моста, проверка на реальном видео Webots.

## Проверка и границы

`npm ci`, `npm test`, `npm run build`, `npm run test:e2e`; CI дополнительно собирает Docker.

Предпросмотр остаётся упрощённым: не моделирует полноценные приоритеты конфликтующих потоков, дорожную физику, все ограничения поворотов и перестроения. Траектории идут по сегментам OSM; на резких углах локальная визуализация может отличаться от сглаженной поверхности. Реальную геометрию можно править инструментом скругления с сохранением в OSM. Нет подтверждения прохождения серверного пайплайна и точности всей сети без прогонов и сверки с местностью.
