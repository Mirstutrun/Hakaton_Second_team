# Архитектура RoadForge 3D

## Границы модулей

Стек: Vue 3 Composition API + TypeScript + Vite + Pinia + Babylon.js. Сервер, база данных, внешние ключи и картографические API для локального сценария не нужны.

| Каталог | Ответственность |
| --- | --- |
| `src/core/osm` | XML, индексы, транзакции, валидация и экспорт; без Vue и Babylon |
| `src/core/geo` | Обратимая локальная проекция, X — восток, Z — север, метры |
| `src/engine` | Engine/Scene, камеры, picking, привязка и обновление meshes |
| `src/engine/geometry` | Дорожные ленты, разметка, стрелки полос, здания и арки |
| `src/stores/editor.ts` | Состояние документа, выбранный объект, история, инструменты |
| `src/editor/tools.ts` | Типы инструментов, горячие клавиши, подсказки |
| `src/components` | Vue-панели и жизненный цикл viewport |

## Источник истины

`OsmDocument` содержит `XMLDocument`, индексы `nodes`, `ways`, `relations` (`Map<string, Element>`) и счётчик `nextId: bigint`. ID всегда строки. Индексы указывают на элементы того же XML. Исходные XML-атрибуты, неизвестные теги, отношения, комментарии, bounds и объекты за bounds сохраняются. XMLSerializer может нормализовать XML-синтаксис; побайтовое равенство исходному файлу не обещается. Семантическое равенство полного дерева проверяется тестом.

Новые положительные ID превышают все ID объектов и все ссылки `nd`/`member`, включая внешние. Это локальные идентификаторы для файла симулятора, не выделенные сервером OpenStreetMap ID. Прямой upload в OSM API не предусмотрен. Новые узлы вставляются перед ways, новые ways — перед relations. Неизменённые элементы и метаданные не переписываются.

Отношения выгрузки могут ссылаться на внешние объекты. В `example.osm` таких ссылок 72 471. Валидатор сообщает одно агрегированное предупреждение; он не удаляет отношения и не подгружает сеть. Отсутствующий узел существующего way — ошибка, блокирующая импорт/экспорт.

## Публичные контракты

```ts
parseOsm(source: string): OsmDocument
serializeOsm(document: OsmDocument): string
validateOsm(document: OsmDocument): ValidationIssue[]
applyEdit(document: OsmDocument, command: EditCommand): EditPatch
applyPatch(document: OsmDocument, patch: EditPatch, direction: 'before' | 'after'): void
createProjection(origin: Coordinate): {
  project(coordinate: Coordinate): LocalPoint
  unproject(point: LocalPoint): Coordinate
  origin: Coordinate
}
```

`applyEdit` изменяет XML и индексы на месте. Он сохраняет снимки только затронутых элементов в `EditPatch.changes`. При ошибке восстанавливает эти элементы и выбрасывает исключение. Счётчик ID монотонный, поэтому отменённые ID не выдаются повторно. Patch не зависит от движка или UI; история хранится в памяти сессии.

`RoadPoint` — `{ lat, lon }` либо `{ nodeId }`. Второй вариант означает настоящий общий OSM-узел. Совпадение координат без общего ID не соединяет дороги.

| Команда | Поля | Результат / защита |
| --- | --- | --- |
| `set-tags` | `target: Selection`, `tags: Record<string, string \| null>` | Только указанные теги; null/пустая строка удаляет тег |
| `create-road` | `points: RoadPoint[]`, `tags: Tags` | Way, новые узлы по необходимости, минимум две разные точки |
| `move-node` | `id`, `coordinate` | Обновляет общий узел для всех дорог |
| `insert-node` | `wayId`, `index`, `point` | Вставляет перед вершиной index, только внутри существующего сегмента |
| `remove-vertex` | `wayId`, `index` | Оставляет минимум две вершины; защищает общие узлы, узлы с тегами и участников relations |
| `delete-way` | `id` | Блокируется при членстве в relation; узлы не удаляет |
| `connect-roads` | `wayId`, `nodeId`, `target` | Клавиша J для несоединённых дорог: близкий свободный конец подтягивается, далёкий — дорога продлевается |
| `delete-building` | `wayId` | Удаляет контур здания; здания не редактируются |
| `mark-building-passage` | `wayId`, `buildingId` | Делит дорогу по стенам: участок внутри — `tunnel=building_passage`, подъезды без отрицательного `layer` |
| `connect-lanes` / `disconnect-lanes` | полоса подъезда, перекрёсток, полоса выезда | Связь полос `type=connectivity`; создаётся горячей клавишей J (`planLaneLink`) |
| `add-bus-stop` | `wayId`, `index`, `point`, `side` | `stop_position` на дороге, платформа слева/справа и `stop_area` |
| `rename-bus-stop` / `remove-bus-stop` | `id` | Меняют или удаляют остановку вместе с платформой |
| `create-bus-route` / `delete-bus-route` | остановки по порядку | Отношение `type=route` + `route=bus` |
| `connect-crossing` / `attach-endpoint` | из предупреждения аудита | «Соединить узлом» / «Замкнуть разрыв» |

`Selection = { type: 'node' | 'way'; id: string }`. В Pinia используйте `selectOsmElement`, `execute`, `undo`, `redo`. Не изменяйте XML напрямую из компонентов. `execute` публикует `lastPatch` и увеличивает `revision`; обработчик сцены вызывает `refreshChangedMeshes(patch)`. Сохранённый курсор истории определяет dirty-state; новая правка после Undo корректно отбрасывает ветку Redo.

## Сцена

Один `SceneManager` создаётся после mount canvas. `Engine`, `Scene`, камера и meshes не помещаются в Vue reactive. XML-документ хранится через shallowRef/markRaw. На unmount отменяется цикл рендера, отключается ResizeObserver, освобождаются Scene и Engine.

Индексы `wayMeshes` и `signalMeshes` (маркеры остановок) связывают OSM ID с группой meshes. Metadata содержит `type`, `id`, `role`; пользователь выбирает реальный OSM-объект через picking. Mesh не хранит отдельную редактируемую копию дорожных данных.

`refreshChangedMeshes` пересоздаёт затронутые ways и маркеры остановок. Если изменён узел, обновляются все использующие его ways, в том числе здания. Остальные meshes и камера остаются. Материалы переиспользуются; старые meshes освобождаются. Маркеры показываются только у выбранного объекта.

Плоскость рисования — уровень 0. Привязка в пределах 8 м ищет узлы существующих наземных дорог, не соединяет случайно мосты и туннели. Вставка узла и остановки проецируются на ближайший сегмент конкретного way; сторона остановки определяется краем дороги, у которого кликнули. Перенос вершины работает в горизонтальной плоскости с обратным преобразованием в lat/lon и создаёт одну команду при отпускании мыши.

Дорожная ширина использует положительный `width`, иначе `lanes × 3.4 м`. Для пешеходных типов — 2.2 м. Визуальные значения по умолчанию никогда не добавляются в XML. `oneway=-1` поддерживается формой и стрелкой. `layer` / bridge / tunnel меняют высоту. Здания экструзированы из way-контуров, высота берётся из height или building:levels, иначе 12 м визуально.

## Расширение

Новый инструмент: добавьте тип и подсказку в `editor/tools.ts`, обработчик picking в SceneManager, семантическую команду и тест в ядре. Для нового объекта добавьте builder в `engine/geometry`, metadata с OSM ID и его адресное освобождение/обновление. Новые панели должны обращаться к существующему store.

Разделение way, редактирование relations, направленная связность, multipolygon-здания и геометрия перекрёстков требуют отдельных изменений. Согласуйте изменения публичных типов с интегратором до реализации.
