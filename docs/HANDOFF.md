# Передача основы RoadForge 3D

## Стек и запуск

Зафиксирован Vue 3 + TypeScript + Vite + Pinia + Babylon.js. Не вводить второй движок или UI-фреймворк. `npm ci`, `npm run dev`; сборка `npm run build`, тесты `npm run test`, браузер `npm run test:e2e`. Полное приложение — в `feat/foundation-3d`.

Работайте в существующем checkout. Каждая облачная задача уже изолирована; отдельный Git worktree без запроса пользователя не требуется. Не меняйте пользовательское Git-авторство и не добавляйте AI-соавторов. Основная ветка для совместной работы должна содержать оба PR.

## Что работает

Импорт произвольного корректного OSM XML, локальный пример 5 МБ, 861 дорожный way, 365 зданий и два исходных светофора. 3D-орбита, ортографический 2D, масштаб и панорама. Выбор и поиск по ID, свойства дорог, направлений, полос, мостов и уровня. Рисование реальных ways, привязка к общим наземным узлам, вставка и перенос вершин, безопасное удаление. Светофоры создаются на дорожной сети, редактируются и удаляются. Undo/Redo, dirty-state, подтверждение удаления и замены несохранённого документа. Экспорт, повторный импорт, защита от неверного XML и битых дорожных ссылок.

Интерфейс включает слои зданий/разметки/пешеходной сети, информацию об OSM-объекте и валидации. Пешеходные дороги отличаются от автомобильных. У `oneway=-1` стрелка направлена против порядка узлов.

## Структура и контракты

Точное описание каталогов, модели, команд и жизненного цикла — в [architecture.md](architecture.md). Ключевые правила:

1. XML и Map-индексы `OsmDocument` — единственный источник истины. ID — строки. Данные не выводятся обратно из Babylon meshes.
2. Vue вызывает `store.execute(EditCommand)`. Ядро возвращает транзакционный `EditPatch`; исключения откатывают затронутые элементы.
3. Undo/Redo применяет `before`/`after` снимки, не копирует весь файл после каждой команды. `revision` уведомляет UI, `lastPatch` — сцену.
4. `SceneManager` владеет одним Engine/Scene. XML и движок не проксируются Vue. Dispose обязателен при размонтировании.
5. Metadata meshes: `{ type, id, role }`. `wayMeshes` / `signalMeshes` связывают модель и сцену. Перенос общего узла обновляет все затронутые ways. Материалы переиспользуются.
6. Новый инструмент добавляется в `editor/tools.ts`, затем в обработчик сцены; изменение модели — отдельной командой ядра. Новый 3D-объект получает builder и явные правила refresh/dispose. Не создавайте собственную копию OSM в панели.

## Ограничения и известные упрощения

- Основной допуск ещё не подтверждён тремя серверными видео. Выполнить официальный прогон до передачи результата жюри; хранить токен вне Git.
- Отношения содержат 72 471 внешнюю ссылку из исходной частичной выгрузки. Они сохранены, не считаются новыми ошибками и не загружаются автоматически.
- Нет split-way и редактора relations. Атрибуты применяются ко всему way; удаление участников relations блокируется.
- Нет анализа направленной связности, дорожных ограничений и согласованности всех `turn:lanes`/других производных тегов. Неизвестные и зависимые теги сохраняются; транспортную семантику должен проверить следующий участник.
- Перекрёстки визуально состоят из перекрывающихся лент, без сложных бордюров и дорожных сопряжений. Сглаживание резких поворотов и полноценная топология перекрёстков — следующие задачи.
- Здания построены из way-контуров. Multipolygon-relations, отверстия, рельеф, точная этажность и дорожные сигнальные фазы не визуализируются.
- Положительный `width` имеет приоритет над расчётом по полосам. Высоты и ширины по умолчанию только визуальные.
- Рисование новой дороги выполняется на уровне 0; привязка к мостам отключена. Геометрия существующих уровней редактируется отдельно.
- При удалении дороги или вершины неиспользуемые узлы сохраняются. Это безопаснее автоматического удаления тегированных и связанных объектов, но очистка orphan-узлов пока не реализована.
- Светофор перемещает свой OSM-узел, поэтому меняется геометрия всех использующих его ways. Отдельного переноса сигнала на другой way пока нет.
- Нет автосохранения/IndexedDB; история живёт в памяти вкладки и пока не ограничена по числу команд. Экспортируйте долгие сессии.
- Production Babylon chunk около 6 МБ до gzip; сборка предупреждает о размере. Переход на точечные импорты и batching — задача графического участника. Отдельного бенчмарка FPS не проводилось.
- Интерфейс адаптивный, но основное редактирование и автоматический сценарий проверены мышью на desktop. Полноценный touch UX не подтверждён.
